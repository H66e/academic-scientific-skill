# 从问题到可核验候选

探索科研方向、生成或改进选题时读取。项目字段遵循 [data-contract.md](data-contract.md)；需要查论文时再读 [literature.md](literature.md)。

## 先确定要解决的问题

用一句话写清对象、现象、条件和为什么值得研究。把用户的兴趣、资源约束与暂未核验的假设分开，避免把宽泛的“AI”直接压成某个热门模型方案。

先判断用户当前需要方向地图、已有想法的改进，还是可以执行的候选。请求只找论文时提供文献，不自动扩大到完整立项流程。

信息不全时可以先列少量问题假设，明确哪些回答会改变路线；不要默认用户拥有 GPU、私有数据、实验账号或固定投稿目标。

一条有研究价值的路径应解释：现有认识是什么，哪里存在可检验的不确定性，消除它会改变什么判断，以及哪些现有办法可能已经解决它。

## 区分贡献类型

选择当前核心 `research_type`；混合项目解释其他部分的作用。类型影响证据义务，不构成价值高低排序。

| 类型 | 主要贡献对象 | 优先验证的内容 |
| --- | --- | --- |
| `empirical` | 方法、机制或条件下的实证规律 | 同设置对照、替代解释、增益不确定度及适用边界 |
| `theoretical` | 命题、界、等价、可识别性或反例 | 假设是否成立、关键证明义务、反例条件及已有定理的包含关系 |
| `measurement` | 构念、诊断工具或评价偏差 | 测量对象是否明确，能否隔离混杂，指标对目标是否有效 |
| `dataset` | 具有研究用途的数据与覆盖 | 来源和使用权限、质量、代表性、泄漏风险及已有数据能否替代 |
| `reproduction` | 已有结论的可靠性与适用范围 | 原结论和复现设置、实现差异、结果不确定度及失败归因 |

理论项目不强制 benchmark 或 GPU 试验；证明尝试可以以一个关键引理或反例搜索为下一步。测量和数据集项目可以研究评价与覆盖本身，不必伪装为模型方法。

复现价值可来自可靠性、协议纠错或新的适用边界；若仅逐步重做且没有新的研究问题，应明确其训练或核验用途，不把它包装成新方法。

## 从文献识别真正的空白

区分作者明确承认的局限与读者根据证据推断的局限，引用相应 `evidence_ids`。只读摘要不能据其省略内容断言全文没有比较、控制或证明。

以下信号值得进一步验证，但不自动构成选题：

- 某个保证依赖现实设置难以满足的承重假设。
- 结果在改变协议、数据或资源条件后出现矛盾。
- 指标改善无法说明目标能力改善，可能存在捷径或混杂。
- 同一机制在别的领域已有实现，尚不清楚迁移条件。
- 历史失败的明确瓶颈已经发生可核验的变化。
- 关键结论难以复现，且差异可能影响领域决策。

Future Work、论文数量少、技术组合从未出现、某任务还没使用某模型，都只是发现线索。问“缺失的知识是什么”，以及补上它是否比已有解决方案更有用。

保留反证：瓶颈可能已被替代方法绕开；负面结果可能只是设置不匹配；所谓空白可能是不值得解决或缺乏可区分答案的问题。

负面证据也可驱动选题：反例、测量失效和不可复现不必改写成全局 supports。用候选的 evidence_links 说明它反对已有认识还是候选自身假设；后一类不能只因“有深读证据”就成为 GO 依据。修正问题或主张后保留原条件，再评审新版本。

把局限写成带条件的判断，例如“在 X 条件下，来源未验证 Y；若 Z 已成立，则此空白不再适用”，不要写成整个领域的绝对缺陷。

对影响选题的 gap 完成一条可追溯核验链：**已知条件 → 来源中的实际观察 → 仍缺失的知识 → 最强替代解释或绕行方案 → 实际执行的反向检索 → 检索后仍成立的边界 → 能区分解释的测试**。反向检索找已解决该问题、换名等价、简单办法绕开瓶颈或证明此问题不成立的工作；记录真实 query、命中与未读部分。只列查询计划时仍标待核验。

来源观察不等于“全领域没有答案”。若替代方案已解决同一问题，撤回原 gap，或据真实条件差异收窄；若原文缺页或检索失败，保留未知。gap 可以来自冲突、缺乏验证、理论条件、测量或覆盖问题，类别只是思考提示，不能靠分类标签证明新颖性。轻量核验可保存在 [gap 卡](research-outputs.md)，无需先创建 dossier。

反向检索的查询不只重复候选名称：用缺失知识、替代解释、等价操作和条件边界描述问题，实际检查命中是否解决同一对象与条件。对最强已有解决方案写清为何仍不足，或据它修正问题。检索词和命中都应可追溯；没有运行或没有读到判定所需内容时，不能把这个环节打勾为完成。

## 生成少量深候选

先独立提出问题与可能解释，再用文献检查并重开思考；不要让第一批检索结果或预设解决方案决定所有方向。

可用的思考动作包括：审计承重假设、寻找反例、隔离混杂、改变信息来源、发现等价关系、重述可解对象、研究复现边界。它们是启发，不是候选必须套用的模板。

优先写最有信息量的候选，不规定必须生成多少条。资源不足、证据不够或问题已解决时允许零个可推荐候选，并给出具体缺口或下一项信息测试。

每个候选说明其核心推理链；增加组件时解释它产生什么、谁消费它、移除后会失去什么能力。没有必要性证据的组件留作备选，不用复杂度充当创新。

成熟候选还应说明其科学后果：假设成立、被有效反驳或只在某些条件成立时，分别改变什么认识或决策。性能、成本或实现改进可以具有研究价值，但须说明它揭示的规律、机制或权衡，不能只把工程产出改名为科学贡献；不强迫每个初步想法填写固定表格。

诊断与消融通常是验证手段；只有测量本身回答核心研究问题时，才把它当主要贡献。不要机械禁止方法中使用诊断信号，判断它是否真正参与决策或学习。

候选尚无足够来源时可以初步构思，但 `evidence_ids`、`search_ids` 为空必须保持 `novelty.status=unclear`，不能把猜测升级为查新结果。

## 对照最近工作写差异

最近工作指技术上最接近的先例，不等于发表时间最新。按研究问题、机制、关键假设和结论寻找近邻，包括其他领域对同一操作的命名。

在 `nearest_work` 中逐项写具体 `delta`，可选择以下真正相关的维度：

- 解决的问题与输入、输出是否不同；差异是否有科学价值。
- 同假设下机制是否已经等价，或已有定理是否包含拟议命题。
- 数据、训练信息、评价协议和计算预算是否可比。
- 改变的条件是否解除真实瓶颈，而非只缩小适用范围。
- 测量构念、数据覆盖或复现结论是否产生新的可核验认识。

“更强模型”“更高分”“换一个任务”不是完整的差异论证。若有意义的贡献只是增量，诚实标为 `incremental`，不强行改写成颠覆性创新。

决定性近邻引用相关全文章节，标记 `decisive=true`；无法读取时保留 `unclear` 和需要核验的段落。不要用标题相似、嵌入分数或相似维度计数直接决定重复。

## 先设计能够推翻想法的验证

每个成熟候选的 `hypothesis` 写可判断的主张，`validation.prediction` 写它成立时应观察或证明什么，`validation.falsifier` 写什么会使核心解释不成立。

`validation.design` 优先区分核心解释与最强的合理替代解释。选择相关且有竞争力的朴素基线，而不是最容易战胜的旧实现；命名尚待核验的基线并保留未知。

把每个会改变决定的替代解释对应到一个控制或诊断，再说明该控制的失效条件。例如增益也可能来自额外信息或计算量，先匹配这些条件；若干预未生效、测量不稳定或样本不足，结果只能无结论，不能自动支持或反驳机制。按贡献类型选择有判别力的对应关系，不要求所有项目都有同样的消融数量。

- 实证：公平控制数据、监督信息、模型能力和算力，先检查简单方法能否解释增益。
- 理论：与最近定理比较条件和结论，尝试最小反例、退化情形及关键证明步骤。
- 测量：控制已知混杂，检验工具对目标变化敏感、对无关变化稳定。
- 数据集：比较已有数据的替代能力，抽样审查质量、覆盖与重复，避免测试泄漏。
- 复现：明确版本和协议差异，把环境失败与科学结论不一致分开。

`validation.metric` 随类型选择：可为效应及不确定度、证明义务、反例判据、构念有效性或覆盖分析。不能仅以有一个 benchmark 分数认定可检验。

`validation.resource_estimate` 写依据、单位、区间和主要未知；不得通过修改用户算力上限来把不可行改成可行。当前只能核验依赖时使用 `feasibility.status=pilot_only`。

`validation.stop_rule` 与实际预算和信息价值匹配，不固定所有项目的天数或提升阈值。区分继续、修订、停止和无结论；控制失效或运行失败不构成科学证伪。

不在构思阶段假装得到实验数据、证明结果或已执行的 dry run。实际执行后按合同记录 `pilots`；smoke 只支持流程可运行，不能支持科研主张。

## 候选输出与下一步

候选记录使用合同的必需字段；用户可读分析可以补前提、替代解释、局限来源与待核验问题，但不要重建评分或决策枚举。

把“已知”“据证据推断”“待验证”分开表达。原始观察通过 `evidence_ids` 追溯，候选的 claim、role、target 与 relation 通过 `evidence_links` 明确；跨论文综合是分析，不伪装成某篇论文的原话。研究动机的反证与候选假设的反证分开，不能给一条全局证据 role 后通用于所有候选。

用户需要比较或决策时，再进入评估流程。排序不能替代查新、可行性和验证前置条件；HOLD 可以附带小规模的信息测试，不保证最终能形成论文。

避免“Oral 级”“必录”“成功概率”等包装。会场历史模式最多是启发，录用结果也不能证明某个单独创新动作有效；分数是有依据的相对判断。

改动问题、机制、假设或验证设计时递增 `idea.version`，按合同重新获取指纹和复核。保存失败条件与重访条件，避免把一次失败方向永久列入禁区。

输出说明推荐的下一步、为什么值得做、什么证据会改变决定，以及目前未核验的部分。产生候选不强制多 agent；进入完整验证前按合同取得当前独立 GO 回执。证据不足时先给 HOLD 与信息测试，而非用低成本 pilot 绕过关键门槛。
