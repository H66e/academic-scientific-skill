# 候选评估与下一步决策

用于评估、比较候选及决定是否投入下一步。记录字段和枚举以 [data-contract.md](data-contract.md) 为唯一规范；本文说明如何判断，不新增第二套评分或状态。

## 先明确评估对象

- 把候选写成具体问题、可检验假设和预期贡献；理论、测量、数据集、复现按核心贡献类型评估。
- 沿用用户选择的方向、目标与约束。默认目标是科学价值；用户明确看重学习、复现或工程产物时，说明其价值，不能暗换成顶会录用目标。
- 评估的是当前版本在当前资源下值得执行的下一步；原型能跑通、模型能写代码、文献存在空白都不等于贡献成立。
- 若用户只请求评估，给决策与有边界的验证建议。GO 不代替实验执行、外部写入或投稿的授权。

## 资源与前置条件

先读取 `project.constraints` 和用户已提供事实。逐项区分资源来源：

- confirmed：用户已确认的设备、时间、预算、数据权限或可投入工作量；保留限制和单位。
- unknown：尚未确认；已有实验配置和公开租赁价格只能帮助估算，不能替用户承诺资源。
- 以上是来源说明，不是 dependency.status 的新枚举。依赖仍使用 `met`、`failed`、`unknown`，依据写进 `basis`。

持久记录中，用于资源约束 KILL 的 project.constraints 条目须有 status=confirmed、实际 value 和 source；decision_basis.constraint_keys 指向这些条目。确认标签只声明实际来源，不证明其诚实；不能把旧自由文本约束自动升级为用户确认。

约束必须对应当前阶段实际失败的必需依赖，写出“该任务需要什么—已确认上限或权限是什么—为何不能满足”的关系。一个无关的已确认事实不能支持资源 KILL；只有 blocked 标签也不能省略失败依赖与相关约束的关联。具体关联字段遵循合同。

把会阻止当前验证任务的条件写入 `feasibility.dependencies`，明确 `mandatory`：

| 前置条件 | 判断时需要的依据 |
| --- | --- |
| 数据和使用权限 | 能获得哪个版本、许可与处理条件；公开描述不等于已可使用 |
| 算力与运行费用 | 模型规模、内存、训练或推理量、次数、可用设备与预算区间 |
| 实现与方法条件 | 关键库、硬件、标注、测量或证明所需前提是否成立 |
| 时间与人工 | 当前任务的工作量估计、人员能力及可用时间；区分已知与假设 |

估算写出依据、范围和最大未知项；没有足够信息时留 unknown。不能把“通常有一张 GPU”作为 met。
非必需增强项不可伪装成硬门槛；必需依赖 failed 时，高价值和高差异贡献不能抵消阻塞。
`ready` 表示当前验证任务的前提已具依据，不能解释为实验将成功。
`pilot_only` 表示目前只能核验前提，决策为 HOLD，并建议一次有预算边界的信息测试。
`blocked` 要有当前任务必需条件无法满足的依据；`unknown` 不能改写成 blocked。
核验任务所需资源可以很少，也可以超过数周；不设统一两周期限。

## 差异贡献与问题依据

- 读取实际检索边界及最接近工作；标题相似、术语不同、引用少都不能独立确定等价或新颖。
- 对决定性近邻比较问题、假设、机制、条件、评价和结论，并定位相关全文章节。
- `distinct` 和 `incremental` 都可能有科学价值；增量工作不因“已有类似研究”自动淘汰。
- `duplicate` 需要当前候选贡献与已有工作等价的决定性证据；只换任务名称不支持差异，但仍需确认实际内容。
- 检索失败、空结果、只有摘要、关键全文未读或关键近邻遗漏时，保留 `unclear` 与 HOLD。
- 区分作者陈述的局限、读者推断的缺口和已经验证的问题；论文 future work 是线索，不是问题价值证明。

不统一要求来源 polarity=supports。已有方法的反例、构念无效或复现矛盾可以提供研究动机，候选 evidence_links 须把观察与具体 claim 连起来，并记录 role、target、relation 和是否影响决策。target=problem/nearest_work 的反对可以驱动新问题；decision_relevant 的 hypothesis/prerequisite/validation 被反对时，当前候选保持 HOLD，不能自标“已解决”跳过修改与复评。

## 验证设计：最便宜的决定性测试

优先找能改变下一步决策的最低成本测试。小规模测试只有在覆盖关键假设时才有判别力；规模效应明显时说明其外推限制。
在 `validation` 中写清 prediction、falsifier、design、metric、resource_estimate、stop_rule。
预算同时覆盖最大工作量与终止条件；用户预算未知时给条件方案，不能报告已确认可执行。
默认不执行实验。用户在当前任务中已授权的本地验证可按授权范围执行，不为同一范围重复索取许可。

| 核心类型 | 决定性验证如何落地 |
| --- | --- |
| empirical | 指定强基线、匹配的控制、指标与效应阈值；检验方法干预是否改变关键机制或性能 |
| theoretical | 指定命题、假设和证明义务；尝试最小反例、边界情形或关键引理；数值例子不能代替证明 |
| measurement | 明确测量构念、校准、采样、误差与混杂；检验所观测差异能否由测量偏差解释 |
| dataset | 验证代表性、标注质量、许可、重叠和泄漏；贡献须关联具体评估缺口，规模本身不足 |
| reproduction | 对齐原文版本、配置和评价协议；区分忠实复现、稳健性检查与新条件下的推广 |

对经验性 AI 研究，检查以下决定性细节；其他类型按其证明或测量对象改写，不机械要求 benchmark：

- 强基线：最接近方法、相关的强方法与足够解释效应的简单方法；必要时说明为何某基线不可比较。
- 公平比较：数据、调参、计算、检索及推理预算可比较；预算差异是研究变量时单独报告。
- 生效干预：消融是否真正移除了目标机制；对照是否保持其余因素；名义开关不能证明干预已生效。
- 指标：与假设相连，定义单位、方向、测量协议、最小有意义效应和不确定性。
- 泄漏：训练与测试重叠、预处理、检索语料、提示调优、公开评测污染和选择性报告。
- 稳健性：按问题需要安排重复、种子或不同条件；先验限定判断规则，避免看结果再挑指标。

stop_rule 应区分预算耗尽、执行故障、已达反例条件和证据仍不足。停止运行不能自动产生科学结论。

成熟方案可用简短的“主张—最强替代解释—控制或诊断—控制失效时如何分类”对应表检查判别力；理论项目用包含关系、反例与证明义务替代实验对照。明确正负结果分别能增加什么知识。没有有效判别力时先完善设计，不能靠更大预算或更高评分取得 GO。

## 0–4 分锚点

三个分数分别评价价值、差异和可检验性，不宣称它们具有统计独立性；采用 0–4 整数，未知用 null，并写明缺少什么证据。0 是有依据的最低评价，不能代表未检索或未阅读。
权重仅来自 `config.ranking_weights`；不另造录用概率。feasibility 作为门控，不再混进三个分数。

| 分数 | scientific_value：科学价值 | differentiation：差异贡献 | testability：可检验性 |
| --- | --- | --- | --- |
| 0 | 有依据表明问题或结论没有所声称的科学意义 | 已确认核心贡献等价重复 | 已明确无法区分主张与其相反结果 |
| 1 | 价值局限于很窄的已知设置，影响尚弱 | 差异存在但很小，增加理解有限 | 有测试构想，关键结果仍可被多种解释吞没 |
| 2 | 有明确且有依据的局部问题，解决后增加知识 | 有清楚的增量贡献及可比较的差异轴 | 可执行设计能区分主要主张，控制或测量仍有限 |
| 3 | 对重要问题有实质价值，正负结果均能减少关键不确定性 | 清楚区别最接近工作，改变有意义的条件、机制或结论 | 预测、反证及主要替代解释均有对应判据与控制 |
| 4 | 有充分依据支持重要且较广的知识增益，并明确适用边界 | 对关键未解决问题形成显著新认识，近邻比较充分 | 设计能决定性地区分主张和关键替代解释，误差与边界清楚 |

每个 `score_reasons` 都说明所用证据、判断链与未知项。高分不要求宏大叙事；低分也必须有依据。
价值看问题及知识增益；差异看相对已有工作的新增内容；可检验性看结果能否辨别主张。避免把同一弱点重复扣在三个维度。
`penalties` 仅用于未被维度或门控体现的明确风险，说明原因；不能再次扣必需依赖失败或新颖性低分。
权重敏感性或成对比较可辅助解释排序；候选相互接近时写出偏好的条件，不伪造精确胜率。

分数是按记录偏好计算的排序摘要，算术小数不表示科研判断达到该精度。对接近或有取舍的候选，检查合理权重变化是否反转排序，并说明偏好条件或并列；成对比较只辅助解释，不替换证据门控或把循环偏好强行排成唯一赢家。

需要表达判断稳健性时，可给各维度 low/medium/high confidence，并在 confidence_reasons 说明证据覆盖、直接性、冲突与缺口。置信度不乘进分数，也不是成功或录用概率；同分数的候选可以有不同的不确定性。单改 ranking_weights 只改变相对排序，不使未改科学依据的评审过期。

## GO / HOLD / KILL

| 决策 | 必须满足的判断 |
| --- | --- |
| GO | 科学依据支持一个具体的下一步；合同全部 GO 必要条件满足，资源与停止条件可审查 |
| HOLD | 关键证据、必需资源、有效对照或验证设计尚未知；说明最小补证行动及复评条件 |
| KILL | 当前有效 KILL 评审有与 duplicate、scientific_refutation 或 constraints 类型相符的依据；写明科学框架或当前用户约束的作用范围 |

GO 的最小记录要求、最近工作全文证据、已知分数与依赖状态按合同检查；通过校验仍需人工判断来源忠实性与科学推理。
`pilot_only`、过期评估、缺分数、必需依赖 unknown 和查新不足均 HOLD。摘要级相似性或未发现论文不构成 KILL 证据。
已被反驳的主张可以 KILL 当前版本；执行故障或低功效测试不足以认定主张被反驳。
用户偏好和预算可以终止当前投入，但应写清这是当前目标或资源下的决定，不能推广成方向无价值。

每次评审保存 decision_basis，不只写 reason。duplicate 需引用深读的决定性近邻与等价论证；scientific_refutation 需深读、与候选核心假设冲突的 link，或当前版本有效 scientific/contradicted 产物；constraints 需明确确认的用户约束与当前阻塞，并引用相应 constraint_keys、必需失败依赖。没有评审、只有 duplicate/blocked 标签或失败日志时先 HOLD，避免误淘汰。

recommended_stage 区分 information_test、pilot 和 full_validation。信息测试可以在 HOLD 下推荐，用来查未知前提、全文或评价可用性。GO pilot 也需全部基础门槛满足；完整验证还需明确批准 full_validation 的当前独立 GO 回执及实际文件核验。成本低不是证据薄弱的豁免，pilot 回执不能授权完整验证；不设所有项目都要 GPU、小样本或固定时间的要求。
排序只包含当前合格 GO；允许没有 GO、只有一个 GO 或分数相近，不补齐 Top3。
给出 decision、证据与限制、下一步、预算和复评触发条件；条件不足时返回有信息的 HOLD，不强推一个赢家。

## 自评与独立评估

在候选依赖内容冻结后获取 fingerprint，再记录 review 的 idea_version、review_basis_hash 与当前 decision_contract_version；ranking_config_hash 单独记录排序偏好。旧接口评审必须按合同补依据并复评，不能机械改字段或规则版本号恢复 GO。
默认可做自评；高投入 full_validation 需同版本、同 review_basis_hash、当前决策规则且 recommended_stage=full_validation 的独立 GO 回执。当前最后一次评审可以是 self，但其独立依据不能来自旧版本、过期输入、独立 HOLD 或仅 pilot 的批准。
独立评估者读取用户范围、预算、当前候选和原始证据，自行产生回执；不能只阅读自评结论后换一个审稿人角色。
只有真实独立上下文才写 `kind=independent`，并保存 author_context、不同的 evaluator_context 和可追溯 artifact；三种 persona 或同一上下文的多段评论不形成独立投票。静态校验只核对字段，不能证实独立性、读取深度或回执内容。

获取独立评审时优先使用宿主可用的隔离子代理，只提供原始问题、当前来源和约束；不可用时使用新会话，或在用户已有授权下由外部评审者返回回执。继承构思过程与预期答案的上下文不能仅换角色后自称独立。模型隔离也不等于专家认可。

持久化回执为实际 JSON 文件，记录 artifact_sha256，内容按 data-contract.md 绑定候选、输入和决策。用 `verify-receipts <dossier.json> --root <existing local root>` 或 `rank <dossier.json> --receipt-root <root>` 限定并核验真实文件；裸 rank 不授权 full_validation。检查回执与输入是否一致不证明科学判断正确，哈希也不证明评审者诚实。
决定数周以上投入的近邻等价判断、关键评审争议、数据集或 benchmark 的长期公开影响，也优先采用独立复核。按实际成本与用户计划确定范围，不以固定 GPU 数量或天数作为所有项目门槛。
意见分歧追溯到证据、前提、资源或验证设计；新增证据回到相关检查，不按票数决定科学真假。
模型不可用时保持自评标签并说明限制，完整验证保持 HOLD；其他门槛已满足时可另行评估有界 GO pilot，不模拟已完成的外部评审。
研究问题、资源、关联来源、机制或实验结果改变后，旧评估按合同失效；复核相关判断并重新冻结指纹。候选依赖之外的独立论文或仅排序偏好变化不要求重做该科学评审。

日常判断可先形成 [轻量决策卡](research-outputs.md)；其 GO/HOLD/KILL 是有边界的研究意见，不自动成为已通过脚本核验的 dossier 评审。需要机器排序或回执核验时再升级完整记录。
