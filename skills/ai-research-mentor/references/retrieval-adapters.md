# 检索能力与实际执行

文献任务中需要解释当前覆盖边界、选择可用来源时读取。记录字段遵循 [data-contract.md](data-contract.md)；不安装额外连接器，不把某个工具名称作为必需依赖。

## 使用能力矩阵

各能力可以独立可用，不能排成从网页到代码的单一等级。区分可调用、实际调用成功和内容可读；工具出现在列表中不是已完成检索。

| 能力 | 要记录的实际边界 |
| --- | --- |
| 用户语料 | 给定哪些文件、版本、段落，哪些未读取 |
| 网页发现 | 来源、语言、时间窗、结果截断与排序限制 |
| 学术元数据 | 支持哪些 ID、版本与数据库；身份核对或去重是否完成 |
| 引用扩展 | 后向、前向或相关工作扩展；实际检查到哪里 |
| 正文读取 | 可读全文、相关章节或仅摘要；权限与解析缺口 |
| 代码与产物 | 哪个仓库、提交或数据版本；是否只读了说明 |

对每项记录 `availability=available|partial|unavailable|unknown`、实际工具/语料、`execution=not_run|succeeded|partial|failed` 与限制。预算、截断、限流和阅读范围影响结论强度；能力标签不提高科学分数，也不代替证据门控。

简短任务只说明会影响当前决定的缺口；完整矩阵留在项目报告。有实际调用时可把当时的能力快照放在对应 search 的附加字段 `capability_snapshot`，其内容随该 search 进入关联候选指纹。不要把会话所有工具的变化写成全项目科学约束，导致无关评审过期。

## 适配实际返回

- 实际 query、来源、执行时间和结果列表写入 searches；计划中的检索不冒充执行记录。
- 规范化文献身份和实际读取版本，保存可回到原始页面的链接。预印本与发表版本不重复计作独立支持。
- 调用完成、覆盖充分和阅读全文是不同状态。分页、结果上限和引用图缺失要保留；失败不能解释为没有先例。
- 筛选结果写入 screening，证据定位写入 evidence，候选特定主张与作用写入 evidence_links。不要从搜索片段填 full_text。
- 没有引用图时可以从实际读到的引用手动扩展；没有正文时列出待核验章节，保留 HOLD。不伪造补全记录。

宿主是否联网、来源是否可读以及当前授权决定实际适配方式。能力矩阵只能解释边界，不能保证召回、文献全面性或新颖性。
