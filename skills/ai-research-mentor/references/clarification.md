# 先澄清，再产出

用户提出一个方向后，不要立刻写报告。方向只是一句话，报告需要目标、约束、证据状态和交付标准；这些不同会直接改变问题定义、实验设计和结论强度。先做一轮**高杠杆澄清**：先问 2–3 个真正阻塞的问题，最多 4 个，再动笔。

## 什么时候必须先问

以下任务默认先澄清：

- 用户提出一个方向，要“完整研究报告 / 立项报告 / 开题报告 / 决策报告”；
- 要判断“值不值得做”，但没说资源、时间、团队、数据或成功标准；
- 要写论文/提案，但没说目标 venue、篇幅、语言、是否已有结果；
- 用户的想法还很宽（“想做多模态”“想做 agent”），看不出具体问题与可检验假设。

简单问答、已有明确材料且只要求整理/核对的请求，不必走完整 intake；缺什么补什么，不重复问用户已经说过的内容。

## 一轮问什么（按优先级）

先问“会改变结论”的问题，不问背景介绍。先问 2–3 个真正阻塞的问题；其余合并成一次，总共不超过 4 个。不要逐条挤牙膏，也不要一次抛出长问卷。

1. **目标与用途**：这份报告要支持什么决定？立项/开题、组会讨论、投稿前评估、还是资源申请？读者是谁？
2. **证据现状**：已有论文/想法/预实验/代码/数据？读过哪些全文？是否已经做过检索？哪些只是听说或假设？
3. **真实硬约束（只在用户主动提供时记录）**：时间、算力/设备、数据与访问权限、团队人数。未知就写未知，不设默认值。
4. **成功标准与风险偏好**：什么证据会让你继续、停止或换方向？能接受负结果吗？最担心哪类失败？

可选补问（只在影响判断时）：

- 交付形式：中文/英文、Markdown/Word/LaTeX、目标长度、是否需要表格/参考文献、截止时间；
- 目标 venue 或汇报场合及其页数/匿名/AI 披露规则（必须用户提供，不自行假定）；
- 已有合作者/导师的偏好或既定方向；是否允许联网检索、可访问的数据库/API；已有草稿是否需要保留/改进。

## 怎么问

- 一次给出编号问题，并说明“哪些可以先用默认值、哪些必须回答”；不要让用户面对 20 个问题。
- 只给**非资源类默认值**（语言、格式、结构）。算力、时间、预算、数据权限、venue 规则未知就写“未知”，不要替用户设定；这些默认值会主导实验设计，不能当作可随手确认的锚点。
- 区分**阻塞问题**（答案会改变问题定义/实验设计/结论）与**非阻塞问题**（只影响措辞/篇幅）。阻塞问题没答案时，明确写出假设并继续；不要把假设写成事实。
- 问完后用 3–5 条**意图回述**确认：“我理解你要的是……；硬约束是……；这次不解决……”。用户纠正后再写。
- 用户说“别问了，先出草稿”时，按当前信息做，把所有假设列为“待确认”，并在报告开头放一个简短的“输入假设”框；不要因此编造资源、数据或 venue 规则。
- 用户回答含糊时，追问一次具体化；仍不明确就写“待确认”，不用漂亮话补齐。

## 提问模板（可直接改用）

```text
在开始写这份研究报告前，我需要确认 3 件真正会改变结论的事（不确定的写“未知”，其余我会标为待确认）：

1. 这份报告要支持什么决定？（立项/开题 / 组会讨论 / 投稿前评估 / 资源申请；读者是谁）
2. 现在已有什么？（论文/想法/预实验/代码/数据；哪些读过全文，哪些只是听说/未检索）
3. 什么证据会让你继续、停止或换方向？能接受负结果吗？最担心哪类失败？

补充（不回答就标“未知”，不设默认值）：时间/算力/数据权限/团队人数、交付形式、目标 venue。若只回复前 3 题，我会直接用“未知/待确认”写报告，不替你假设 GPU、预算或时限。

默认假设（仅格式类）：中文 Markdown、按报告结构；不假设 GPU、预算、数据权限、团队人数或 venue 规则。
```

## 回述模板

```text
我确认的理解：
- 目标：……
- 硬约束：……
- 已有证据：……（已读全文：……；仅摘要/听说：……）
- 本次不解决：……
- 交付：……

如果以上有误，先纠正；否则我按这个范围产出报告，未确认项会在“输入假设/边界”中列出。
```

## 澄清后的动作

- 把用户回答整理成报告开头的“输入假设与范围”，逐条标注“用户确认 / 默认假设 / 未知”。
- 用户提供的信息不足以支撑决定性判断时，报告结论保持“待验证/待补证”，并给出补证动作；不要用假设冒充证据。
- **venue 规则永不默认**：页数、匿名、模板、AI 披露只能由用户提供。缺失时可以继续写内容，但格式与投稿相关部分必须标“待用户提供”，不得声称符合某 venue。
- 澄清不是一次性的：报告写到实验设计或结论时，如果发现新缺口，只问一个新的关键问题，不重新盘问全部。
- 不把“用户没回答”解释成“用户同意默认值”；默认值只用于推进，必须在报告中显式可见。
