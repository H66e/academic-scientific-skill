# 从研究判断到可用文稿

用户要决策卡、开题、研究提案、近邻比较、综述或论文草稿时读取。以实际来源和用户结果为依据；证据记录遵循 [data-contract.md](data-contract.md)。文稿结构服从用户目标，不强制固定十二项输出或 Nature 风格。

## 轻量决策卡与 gap 卡

一次判断直接回复；需要保留结论但尚未持续维护时，用 Markdown 卡片保存问题、已知事实、决定性依据或近邻差异、主要未知及下一步。gap 卡按 [ideation.md](ideation.md) 的核验链保留来源观察、缺失知识、替代方案、实际反向检索和判别测试。只保留有实际内容的部分，不用空模板迫使用户填写。

卡片中的 GO/HOLD/KILL 是记录的、有范围的研究意见；不是机器核验通过或实验授权。关键依据不足仍用 HOLD，明确解除条件。不新建 PIVOT 等决策枚举；修订方向可以作为下一步说明。

需要跨轮恢复、追踪来源变化、机器排序或核验独立回执时，再升级为 dossier。将真实事实映射到相应集合，保留版本与来源；未完成检索、阅读或评审的部分留空与待核验，不把卡片直接提升为完整有效评审。

## 轻量输出工具

Node.js 可用时，`scripts/research_outputs.mjs` 提供纯整理工具；宿主先填真实材料，工具不生成科学论证或自动查新。例如一份最小 notes.json：

```json
{
  "question": "在已指定条件下，要解释或验证什么？",
  "type": "measurement",
  "known": ["用户或来源已确认的事实及其定位"],
  "gap": "缺失的知识；尚未核验时明确说明",
  "nearest_work": ["实际读到的近邻、版本、定位与差异"],
  "alternatives": ["最强替代解释或绕行方案"],
  "search_findings": ["实际检索结果及范围；未检索时写未检索"],
  "test": "能区分解释的测试及必要控制",
  "next_step": "下一项有边界的补证或验证",
  "limitations": ["当前仍未知或未读的内容"],
  "decision": "HOLD"
}
```

question 必需；type 和其他说明按任务选用，说明字段用真实文本或文本数组。type 沿用五种 research_type。可另提供符合合同的 constraints、assumptions，保留用户事实及来源；不能从自由文本推断用户已确认算力或时间。

需要拆清 gap 核验链时，按需增加 `source_observations`（所读版本、定位与实际观察）、`reverse_search`（实际调用、命中、未读和未执行部分）、`boundary`（检索后仍成立的条件）及 `scientific_consequence`（支持、反驳或缩窄后会改变什么认识）。这些字段都是笔记，不是自动核验的来源或结果。已有 `gap`、`search_findings` 和 `test` 足以表达时，无需重复填写；未执行时直接写未执行。

```text
node scripts/research_outputs.mjs card notes.json
node scripts/research_outputs.mjs draft notes.json --name project-name
node scripts/research_outputs.mjs bibtex dossier-or-source-records.json
node scripts/research_outputs.mjs draft - --name project-name
```

输入是至多 8 MiB 的 UTF-8 JSON 文件；`-` 从标准输入读取，支持常见 UTF-8 BOM。card 输出简短 Markdown；draft 只生成初步 dossier 的项目问题、类型和显式事实，不伪造 papers、searches、ideas 或 reviews。即使笔记记录了 GO，draft 仍没有获得 GO 的候选。输出到标准输出，用户或宿主在授权目录检查后保存；不覆盖已有研究记录。

bibtex 整理实际 papers 元数据并保留未知，不补造作者、年份或 DOI；BibTeX 输出在 stdout，论文 ID 到引用键的映射及警告在 stderr。它沿 DOI、arXiv 和 OpenReview 的已给定身份关联兼容记录，也处理同时给出 DOI 与 arXiv 的关联记录；不凭标题相似合并。不同 DOI、版本、标题、作者或指定引用键的冲突必须先解决，不能静默选择其一。导出成功不代表文献真实、已读或支持文稿论点，也不把合并后的来源数量作为独立证据数量。

## 按用户请求组织文稿

| 文稿 | 组织重点与依据 |
| --- | --- |
| 开题、研究提案 | 已有认识、限定的 gap、可检验主张、科学后果、判别设计、真实资源与停止条件；预期结果写成预测 |
| 近邻比较 | 逐篇比较问题、机制、条件、评价与结论，引用实际版本和定位；未读部分留未知，标题相似不等于机制等价 |
| 相关工作、综述 | 围绕争议、路线与条件差异综合，交代实际检索边界；结论回到原始研究，不以论文数量替代证据 |
| 带来源的章节草稿 | 让每个关键论点对应实际证据，区分来源报告、跨论文推断与待验证的作者主张 |
| 完整 manuscript | 根据用户提供的真实方法、结果、图表与限制组织论证；缺结果时先交付提案或明确标出待补结果的结构草稿 |

写作前核对对象是提案还是已有研究，以及用户指定的语言、篇幅和会议/期刊要求。开题不预设顶会目标；综述不因范围大就冒称系统综述。需要严格系统检索时，先协商相应范围和记录要求，再按实际执行说明方法。

正式论文的结果、数值、显著性、消融、数据权限和执行描述必须来自真实材料。未执行的设计使用计划性表述；不能为了完成整篇文稿把预期收益写成观察发现。负结果和无结论按 [feedback.md](feedback.md) 分类，不为叙事删去不利证据。

## 实际成稿与核对

先确定文稿要表达的核心问题与结论，再根据现有材料选择结构。开题或提案先写已有认识、仍成立的 gap 和能区分解释的设计；综述按争议或条件组织综合；已有结果的论文让方法、结果和限制共同支撑主张。没有结果时可以交付研究提案或带明确待补标记的草稿，不能把它称为完成的实证论文。

对会改变结论的句子，保留一个简短对应记录：实际来源及版本、章节/页码/图表定位、支持的具体内容，以及这是来源报告、跨来源推断还是待验证主张。可直接写在工作笔记或现有 dossier 中，不要求所有句子另建图谱。一个来源若仅证明特定数据和协议下的现象，正文不得改成普遍机制；引用缺口保留为待核验，不用猜测的论文补齐。

成稿时使用已有身份映射组织正文引用和参考文献；逐项检查正文引用能否找到条目、条目是否确实被引用、关键论点是否仍忠实于所读版本。BibTeX 键存在只能通过前两项形式检查。用户请求正式交付格式时，生成可用文件并用宿主工具检查其渲染或编译；工具不可用时交付可编辑源文件并准确说明尚未验证的部分。

随文稿简短交代实际使用的语料或检索截止范围，以及会影响结论的未读原文、缺失结果和未确认条件。不要把元数据导出、全文下载或模板填充描述为已完成系统综述、深读或独立评审。

## 引文与专业协作

关键论点保留论文版本与可追溯定位；正文引用对应参考文献，BibTeX 键只用于组织，不能取代论点—证据核验。来源无法解析或关键全文未读时，说明缺口，不生成看似完整的引文填补。

宿主存在适合的文献检索、全文解读、学术写作、引文管理、绘图或排版 skill 时，可在用户请求范围内协作，传递原始来源、证据、主张、真实结果和未确认项；本 skill 不依赖外部 skill 才能工作，也不将科研材料自动上传。专业工具负责其具体产物，当前研究主张及证据边界保持清楚。

用户要求 LaTeX、Word、PPT 或图表时采用宿主适合的生成与验证能力，保留同一组真实依据。文稿风格按用户或目标会场要求选择，不要求 Nature 系列来源或某种投稿模板。
