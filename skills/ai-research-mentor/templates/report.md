## 附录：机器可读块

> B/C/D 共用，全文只保留这一份；A 级（concept_memo）删除本节与文末参考文献表。下面 JSON 里的值都是占位符，必须替换为真实检索式、真实论文与真实账本记录；字段与校验口径见 [deep-read-gate.md](../references/deep-read-gate.md)。文末参考文献表同样只有一份：5 列，账本绑定列写实际 `ledger:<id>`；check-draft 会读取该项目的 `evidence.anchor` 与 user/T1 的 `reading.confirm`（section/full_text），自填“已核验”不算，section 级阅读只覆盖带定位的引用。

### 近邻选择与深读记录

```nearest-set-json
{
  "schema": "nearest-set-v2",
  "created_at": "YYYY-MM-DD",
  "queries": ["检索式 1（术语/数据库）", "检索式 2（另一种措辞）"],
  "candidates": [
    {
      "id": "P1",
      "title": "[P1 论文标题]",
      "rationale": "[P1 为什么最接近；可能漏掉什么]",
      "status": "abstract",
      "reader": "model",
      "ledger": "ledger:E1",
      "locator": "无",
      "kill_questions": [
        {"q": "[P1 致命问题 1：若答案是 Y，哪个主张不成立？]", "answer": "未读到", "locator": "无"},
        {"q": "[P1 致命问题 2]", "answer": "未读到", "locator": "无"}
      ]
    },
    {
      "id": "P2",
      "title": "[P2 论文标题]",
      "rationale": "[P2 为什么是第二候选；可能漏掉什么]",
      "status": "section",
      "reader": "user",
      "ledger": "ledger:E2",
      "locator": "§2",
      "kill_questions": [
        {"q": "[P2 致命问题 1]", "answer": "是", "locator": "§2"},
        {"q": "[P2 致命问题 2]", "answer": "否", "locator": "§3"}
      ]
    }
  ],
  "uncovered": ["[可能漏掉的近邻簇：写 id 或标题]"]
}
```

- `schema` 固定为 `nearest-set-v2`；`created_at` 用 `YYYY-MM-DD`；超过 180 天给 stale warning 并阻止 `delivery_ready`，重查是人工动作。
- `queries` 至少 2 条互不相同的非占位检索式（每条至少 4 个有效字符）；`candidates` 至少 2 条。
- `id` 形如 `P1` 且唯一；`ledger` 形如 `ledger:E1` 且唯一；`status` 取 `full_text/section/abstract/unseen`，`reader` 取 `model/user`。
- `full_text` 候选需要账本中的 full_text 阅读；`section` 至少需要 section/full_text 阅读，否则不得声称读过；候选定位要与账本阅读定位一致。
- `abstract/unseen` 候选和答案“未读到”的定位可以写“无”，不要编造章节号。
- 每个候选至少 2 个 `kill_questions`；每条的 `q/answer/locator` 必填，`answer` 只能是 `是/否/未读到`，`locator` 必须是真实章节/表/图/页定位；答 `是/否` 的问题 locator 还要与该候选的账本阅读定位一致，不能只写一个格式合法的 §9。
- `uncovered` 记录可能漏掉的近邻簇；主张等级为 A 时必须把 `abstract/unseen` 候选写进 `uncovered`（写 id 或标题）。
- 全文只能有一份 `nearest-set-json` 与一份 `provisional-json`；同一来源不能通过 anchor/source 两种 id 冒充两个候选。

### 暂定判断（C 级）

- 暂定判断：倾向 P1 与本方向机制等价；置信低，仅基于摘要/未读。
- 翻转条件：[P1 哪一节/哪个结果会推翻暂定判断]。
- 最小核验动作：读 P1 §3.2 与 Table 2，回答 P1 的第一个致命问题。
- 获取路径：arXiv / 作者主页 / 补充材料 / 代码 README / 向作者索取。

```provisional-json
{
  "schema": "provisional-v1",
  "claims": [
    {
      "id": "C1",
      "tendency": "倾向 P1 与本方向机制等价（未读全文，置信低）",
      "flip": "若 P1 §3.2 给出同一机制与适用条件，则暂定判断不成立。",
      "check": {
        "candidate": "P1",
        "question": "[复制 P1 第一个致命问题原文]",
        "locator": "无"
      },
      "access": "arXiv / 作者主页 / 补充材料 / 代码 README / 向作者索取"
    }
  ]
}
```

- 每条 C 级主张恰好一个条目，id 与“主张—证据等级”表一致；`tendency/flip/access` 必须是真实内容；C 级主张的“近邻”列至少填一个候选，`check.candidate` 必须在该候选集合内。
- `check.candidate` 必须在 nearest-set 里；`check.question` 必须与对应候选的某个 `kill_questions[].q` 规范化后一致（不接受改写/转述），且该问题在 nearest-set 里的答案必须是“未读到”（已答“是/否”应升级为 B 级）；`check.locator` 必须与该问题的 locator 一致。
