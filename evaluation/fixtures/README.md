# Fixed regression fixtures

All material in this directory is **synthetic**. It contains no unpublished research, real reading declarations, genuine independent approvals, private project records or provider responses acquired from the network. Passing these cases establishes the recorded software contracts; it does not measure literature recall, scientific value or research effectiveness.

`result-lifecycle.json` is the existing language-neutral result-lifecycle case collection. Its expected scientific states remain unchanged by the removal of the previous runtime.

## Historical toolchain responses

`toolchain-regression.json` freezes **11 groups and 164 complete responses** from the previously maintained implementation at [source commit b2647a94595626f039ef1091cde5f4e5cb908b2b](https://github.com/H66e/academic-scientific-skill/tree/b2647a94595626f039ef1091cde5f4e5cb908b2b). The full response objects and errors were actually captured on 2026-10-10 using the historical runtime version recorded in `toolchain-regression-provenance.json`, before its implementation files were removed. Expected values were not calculated by the current Python implementation.

The one-time private capture script imported the then-current conformance test's case preparation and submitted each batch to the historical executable. Its purpose was to preserve the same input/output comparisons after eliminating that executable dependency. It used the fixed clock `2026-10-10T00:00:00.000Z`, synthetic injected HTTP/DNS responses, public example bytes and temporary synthetic receipt files. No network or model call was made. Capture scripts and executable copies were temporary development tools and are not required to run these tests; historical source remains available at the recorded Git commit. Input preparation used the existing helper for certain current fingerprints and receipt templates; all expected responses came exclusively from the historical executable.

The case groups preserve validation, fingerprints, ranking weights, complete ranking outputs, old/mixed/future contract migrations, binary64 numbers, UTF-16 ordering and offsets, receipt stage/context/score/hash/size binding, cloned or forged verification reports, stale reviews, output unknowns, bibliography identity bridges, source identifiers, address restrictions, offline/partial/error responses, HTML extraction and unextracted PDF bytes. The binary64 case contains the original 256-draw fixed-seed sample together with its boundary values; it is one complete response comparison, not hundreds of independent test methods.

Receipt roots are the sole environment substitution: each captured request's temporary absolute root is replaced by `$RECEIPT_ROOT`, then recreated in a new test-local directory. Receipt bodies retain their original bytes as base64 plus an explicit trailing-space count; their SHA-256 is checked before use. Response values are unmodified. All source text and complete error messages remain frozen.

`toolchain-regression-provenance.json` records the source commit, oracle version, group/case counts and SHA-256 digests of the captured fixture, historical capture inputs and historical implementation files. The historical executable and test-source bytes were restored directly from the stated Git commit to a private temporary directory. Their digests describe Git blob bytes; public example digests describe the exact local file bytes consumed at capture, including platform line endings. Historical filenames are provenance, not active repository paths. The fixture's digest is also pinned in the regression test, so changing both payload and manifest alone does not silently change the expected behavior.

Do not regenerate these expected values from the implementation being tested. An intentional contract change requires review of the affected scientific or encoding behavior, new independent evidence and an explicit migration decision. These frozen comparisons can reveal divergence from the recorded historical cases; they cannot discover arbitrary historical bugs or substitute for tests of later capabilities.

The source commit is `b2647a94595626f039ef1091cde5f4e5cb908b2b`; the capture date, historical runtime version and four implementation Git blob IDs and SHA-256 digests are recorded inside the fixture. Responses came from the still-present historical implementation before deletion, and each original comparison passed. Expected values were never regenerated from the Python runtime.

The original tests retain their deterministic public synthetic input constructors. Their input-batch fingerprints use SHA-256 of Python JSON with sorted keys, ASCII escapes and compact separators; these hashes identify test inputs, rather than a scientific dossier or ledger. The current tests must match those fixed input hashes and compare every response. Evolution fixtures instead recreate the same explicitly named local cases; temporary absolute paths are excluded from the public fixture and its outputs contain no paths. API response values and errors are unmodified. No network request, scientific reading or genuine independent approval was made by this capture. `test_baseline_integrity.py` independently pins the complete fixture bytes, 14 batches, 321 responses and the per-component counts, while consumers reject shortened response arrays.

These module cases complement the 164 complete toolchain responses and the unchanged 41 language-neutral result-lifecycle fixtures. Independent Python assertions also preserve score/gate priorities, candidate-scoped fingerprint closure, administrative versus scientific changes, latest review and peer stage precedence, migration without revived approval, TLS certificate/hostname requirements, and source-to-card/BibTeX workflows without invented reading. They preserve software contracts and do not establish scientific effectiveness.
